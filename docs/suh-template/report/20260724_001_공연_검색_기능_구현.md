# 공연 검색 UI 및 결과 필터 구현

## 개요

기존 헤더의 단일 돋보기 버튼을 제거하고, 사용자가 장르·지역·날짜·인원을 직접 선택할 수 있는 통합 검색 컴포넌트를 헤더 아래에 추가했다. 검색 조건은 URL 쿼리로 결과 페이지에 전달되며, 장르별 페이지에서 검색할 경우 해당 장르가 기본 선택된다. 결과 페이지에서는 기존 장르 페이지의 더미데이터 구조를 참고한 대표 공연 데이터를 조건에 따라 필터링해 표시한다.

## 변경 사항

### 공통 검색 UI

- `code/frontend/src/components/EventSearchBar.tsx`
  - 헤더 아래에서 사용하는 공연 검색 컴포넌트를 신규 작성했다.
  - 검색 항목을 `장르 → 지역 → 날짜 → 인원 → 검색` 순서로 배치했다.
  - 전체, 콘서트, 뮤지컬, 연극, 클래식/무용, 전시/스포츠, 버스킹 장르를 선택할 수 있도록 구성했다.
  - 서울, 경기, 부산, 제주 추천 지역과 전체 지역 초기화 기능을 제공한다.
  - 시작일과 종료일을 선택하고 날짜 조건을 초기화할 수 있도록 구성했다.
  - 시작일보다 빠른 종료일이 남지 않도록 종료일을 초기화하고, 시작일 선택 전에는 종료일 입력을 비활성화했다.
  - 관람 인원은 1명 이상만 선택할 수 있도록 증감 버튼을 적용했다.
  - 선택한 검색 조건을 `category`, `region`, `startDate`, `endDate`, `people` 쿼리로 구성해 `/search`로 이동한다.
  - 현재 경로에 따라 장르별 페이지의 장르를 기본 선택하며, 사용자가 전체 또는 다른 장르로 변경할 수 있도록 했다.
  - 검색 결과 페이지에서는 URL 쿼리의 기존 검색 조건을 복원한다.
  - `/mypage` 및 하위 경로에서는 검색 컴포넌트를 표시하지 않는다.

### 검색 결과 화면

- `code/frontend/src/pages/SearchResultsPage.tsx`
  - 검색 결과 전용 페이지를 신규 작성했다.
  - 장르별 페이지에서 사용한 데이터 구조를 기준으로 장르별 대표 더미데이터를 구성했다.
  - URL 쿼리에서 장르, 지역, 시작일, 종료일, 인원 정보를 읽는다.
  - 장르가 `all`이면 전체 결과를 표시하고, 특정 장르이면 해당 장르만 표시한다.
  - 공연 주소에 선택 지역이 포함되는지 확인해 지역 조건을 적용한다.
  - 공연 기간과 선택 기간이 겹치는 경우에만 날짜 조건을 충족하도록 처리했다.
  - 검색 조건 요약과 결과 개수를 표시한다.
  - 조건에 맞는 결과가 없을 때 별도의 빈 결과 안내 화면을 제공한다.
  - 직접 수정된 비정상 인원 쿼리는 1명으로 보정한다.

### 라우팅 및 전역 배치

- `code/frontend/src/App.tsx`
  - `EventSearchBar`를 `Header` 바로 아래에 배치했다.
  - `/search` 경로에 `SearchResultsPage`를 연결했다.
  - 검색 결과 URL의 쿼리가 변경되거나 브라우저 뒤로가기·앞으로가기를 사용할 때 검색바 상태가 URL과 일치하도록 재마운트 키를 적용했다.
  - 끝 슬래시가 포함된 `/search/` 경로도 동일하게 처리하도록 경로를 정규화했다.

### 헤더 정리

- `code/frontend/src/components/Header.tsx`
  - 기존 돋보기 검색 버튼과 `/search` 직접 링크를 제거했다.
  - 검색 진입점을 헤더 아래의 공통 검색 컴포넌트로 일원화했다.

## 주요 구현 내용

### 화면별 기본 장르

검색 컴포넌트는 현재 경로를 정규화한 뒤 장르를 결정한다.

| 현재 화면 | 기본 장르 |
|---|---|
| 홈 및 일반 화면 | 전체 |
| `/concert` | 콘서트 |
| `/musical` | 뮤지컬 |
| `/play` | 연극 |
| `/classic` | 클래식/무용 |
| `/exhibition` | 전시/스포츠 |
| `/busking` | 버스킹 |
| `/search` | URL의 `category` 값 |

장르 페이지에서 기본값이 설정되더라도 검색 전 사용자가 전체 또는 다른 장르를 선택할 수 있다.

### 검색 조건 전달

검색 조건은 React Router의 페이지 상태가 아닌 URL 쿼리로 전달한다. 이 방식으로 검색 결과 URL을 새로고침하거나 공유해도 동일 조건을 다시 읽을 수 있다.

```text
/search
  ?category={장르}
  &region={지역}
  &startDate={시작일}
  &endDate={종료일}
  &people={인원}
```

지역과 날짜가 선택되지 않은 경우 해당 쿼리는 생략하며, 장르와 인원은 항상 포함한다.

### 검색 결과 필터

결과 데이터는 다음 조건을 모두 만족하는 경우에만 표시한다.

1. 전체 장르이거나 이벤트 장르가 선택 장르와 일치한다.
2. 전체 지역이거나 이벤트 주소에 선택 지역이 포함된다.
3. 선택 시작일 이후에도 공연이 진행 중이다.
4. 선택 종료일 이전에 공연이 시작된다.

인원 정보는 현재 더미데이터에 잔여 좌석 또는 수용 인원 필드가 없으므로 결과 필터에는 사용하지 않고 검색 조건 요약에만 표시한다.

### 상태 복원 및 경로 처리

- `/search`에서는 URL 쿼리를 검색바의 초기값으로 사용한다.
- 검색 쿼리가 변경되면 검색바를 새로 마운트해 표시값과 결과 조건의 불일치를 방지한다.
- `/concert/`, `/search/`처럼 끝 슬래시가 있는 경로도 동일하게 인식한다.
- `/mypage`와 `/mypage/*`에서는 검색바를 숨기되 비슷한 이름의 다른 경로에는 영향을 주지 않는다.

## 주의사항

- 검색 결과는 현재 장르별 대표 더미데이터 6개를 사용하므로 실제 서버 데이터와 연결되지 않았다.
- 인원 조건은 좌석 재고 데이터가 추가된 뒤 실제 필터에 반영해야 한다.
- 지역 선택은 현재 서울, 경기, 부산, 제주 추천 항목으로 제한되어 있다.
- 날짜 선택은 브라우저 기본 날짜 입력 UI를 사용한다.
- 전체 프로젝트 ESLint에는 기존 파일의 선행 오류가 있으므로 이번 검증은 검색 기능 관련 변경 파일을 대상으로 수행했다.
- `.vscode`는 작업 시작 전부터 존재한 사용자 파일이며 이번 변경 범위에 포함하지 않았다.
